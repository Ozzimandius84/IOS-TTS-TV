Google (job 26b): the consent page opens in the system browser, and the redirect comes home through Rust

The flow is TTSTV's -- library/drive.js makes the PKCE challenge, exchanges the
code and keeps the tokens. This crate owns the two halves a web page has no key
to, and nothing else.

ONE: google_sign_in opens the URL the page hands over, and refuses anything that
is not https://accounts.google.com/o/oauth2/v2/auth?. Google refuses its consent
page inside an embedded web view (disallowed_useragent) and RFC 8252 section 8.12
says the same from the other side: a person cannot see what they are typing a
password into if the app drew the window. tauri-plugin-opener does the opening --
the one new dependency, and there is no stdlib way to open a URL from an iOS app
-- and it is granted NO page permission, so this command is the only door to it.

TWO: the redirect (com.googleusercontent.apps.<n>:/oauth?code=...) arrives through
the deep-link plugin already registered for frank-pair://, is sorted by
is_google_redirect, held in PendingGoogle, and written into localStorage
["ttstv.sync.googleRedirect"] by flush_google. Read in Rust, written to the page
from there -- 23d's shape, for 23d's reason: a page that could call get_current()
could read another flow's code out of a launch URL.

TTSTVHost.google and .googleSignIn are injected ONLY when an id is pasted --
absent, not inert -- and the Settings page reads the absence and says so.

src-tauri/google.json is the one place the iOS client id is pasted (empty until
Osca's clicks; studio/STATUS.md job 26 section 6.3). tauri.conf.json's deep-link
scheme is the same fact spelt twice, so tests/test_google_link.py holds them
together: a regex proves no other file carries an id, and the scheme must be
exactly the reverse of google.json's -- or, while it is empty, absent, so a build
cannot advertise a URL type nothing answers. It also holds that the command is
declared, granted and narrow, that opener has no page permission, and that no
client_secret is anywhere: an iOS client has none and PKCE needs none.
